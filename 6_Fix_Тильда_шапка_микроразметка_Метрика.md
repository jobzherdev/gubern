# Фикс: съезжает шапка сайта в Тильде после вставки микроразметки Organization и кода Метрики

**Проект:** festivalcontest.ru (ООО «Губерния», ИНН 4217147207)
**Симптом:** после добавления JSON-LD микроразметки организации и счётчика Яндекс.Метрики вверху страницы появляется пустая полоса, шапка уезжает вниз, строка контактов наезжает на заголовок H1 (особенно заметно на мобильных).

---

## 1. Причина

Ни JSON-LD, ни код счётчика **не занимают места в вёрстке сами по себе**: тег `<script>` имеет
`display: none` по умолчанию. Ломается не код — ломается **место вставки**.

Четыре механизма, дающие ровно такую картинку:

### 1.1. Код вставлен в HTML-блок T123 (или в элемент «HTML» в Zero Block)

Это причина №1. Блок T123 — это полноценная запись страницы: `div.r` → `div.t123` со своими
вертикальными паддингами. Даже если внутри только `<script>`, сам блок остаётся в потоке и даёт
пустую полосу 20–60 px. Если этот блок стоит **выше шапки** — вниз уезжает всё, включая шапку.
Именно так выглядит пустое поле в верхней части скриншота.

В Zero Block элемент «HTML» ещё хуже: он позиционируется абсолютно и имеет заданную высоту в
сетке — блок физически резервирует место.

### 1.2. Код вставлен в поле «HTML-код для вставки внутрь body», а не head

Тильда вставляет это содержимое в начало `<body>`, до `.t-body` / `.t-records`. Любой узел с
ненулевой высотой (перенос строки в текстовом узле, обёртка `<div>`, `<noscript>`) оказывается
первым элементом страницы и сдвигает всё вниз.

### 1.3. Сбит пересчёт отступа под фиксированную шапку

Меню Тильды (ME301, M683, T280 и т. п.) — `position: fixed` / `absolute`. Компенсирующий отступ
следующей записи Тильда считает скриптом при загрузке. Когда между записями появляется лишний
пустой блок, отступ вешается не на тот элемент → контент подлезает под шапку. На скриншоте это
второй симптом: строка контактов и телефон наезжают на H1 «Скидки на участие в фестивалях».

### 1.4. Битый HTML в самом коде

Достаточно одной из этих мелочей, чтобы браузер закрыл теги не там, где нужно, и часть разметки
шапки оказалась внутри сломанного узла:

- «умные» кавычки `«»` `“”` вместо прямых `"` — типично при копировании через Word/Google Docs;
- потерянный `</script>`;
- строка `</script>` внутри JSON (должна быть экранирована как `<\/script>`);
- редактор обернул код в `<p>` или `<div>`.

Отдельный случай — `noscript` Метрики без инлайн-стилей: если при копировании потерялся
`style="position:absolute; left:-9999px;"`, пиксель-картинка встаёт в поток и тянет за собой
типографские отступы Тильды.

## 2. Диагностика за 2 минуты

1. Открыть страницу → `Ctrl+U` (исходный код) → поиск `application/ld+json` и `mc.yandex.ru`.
   - Нашлось внутри `<head>…</head>` — место вставки верное, идти к п. 1.4 (валидность кода).
   - Нашлось внутри `<div class="t-rec">` / `t123` / после `<body>` — это причина, идти к п. 3.
2. DevTools (`F12`) → кликнуть по пустой белой полосе вверху → посмотреть, какой узел
   подсвечивается и какая у него высота/паддинги.
3. Проверить гипотезу: временно удалить (не «скрыть», а удалить) вставленный код → опубликовать →
   открыть страницу с `?v=1` в адресе, чтобы обойти кэш. Полоса ушла — причина подтверждена.

> Важно: код из полей head «запекается» в каждую опубликованную страницу. После любой правки
> нужно **«Опубликовать все страницы»**, иначе часть страниц останется со старым кодом, и картина
> будет разной на разных URL.

## 3. Правильные места вставки

| Что | Куда | Почему |
|---|---|---|
| Яндекс.Метрика | **Настройки сайта → Аналитика → Яндекс.Метрика** — вставить только номер счётчика | Тильда сама подставляет корректный сниппет в head, вёрстку не задевает |
| Метрика с кастомными параметрами (вебвизор, цели, ecommerce dataLayer) | Настройки сайта → Ещё → **HTML-код для вставки внутрь head** | Единственное безопасное место для произвольного скрипта |
| JSON-LD Organization (общий для всего сайта) | Настройки сайта → Ещё → **HTML-код для вставки внутрь head** | Один раз на весь сайт |
| JSON-LD под конкретную страницу (Event, FAQPage, BreadcrumbList) | Настройки **страницы** → Дополнительно → HTML-код внутрь head | Разметка страницы должна жить на своей странице |

**Никогда не вставлять микроразметку и счётчики:**

- в блок T123 «HTML-код»;
- в элемент «HTML» внутри Zero Block;
- в поле «HTML-код для вставки внутрь body»;
- в текстовый блок / поле описания.

## 4. Готовый код для festivalcontest.ru

Вставлять в **Настройки сайта → Ещё → HTML-код для вставки внутрь head**.
Кавычки — только прямые `"`. Перед сохранением заменить значения-заглушки.

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "@id": "https://festivalcontest.ru/#organization",
  "name": "Festival & Contest",
  "legalName": "ООО «Губерния»",
  "url": "https://festivalcontest.ru/",
  "logo": {
    "@type": "ImageObject",
    "url": "https://festivalcontest.ru/ЗАМЕНИТЬ-НА-URL-ЛОГОТИПА.png"
  },
  "email": "info@festivalcontest.ru",
  "telephone": "+7-981-807-01-60",
  "taxID": "4217147207",
  "contactPoint": [{
    "@type": "ContactPoint",
    "telephone": "+7-981-807-01-60",
    "email": "info@festivalcontest.ru",
    "contactType": "customer service",
    "areaServed": "RU",
    "availableLanguage": ["ru", "en", "it"]
  }],
  "sameAs": [
    "ЗАМЕНИТЬ-НА-ССЫЛКУ-VK",
    "ЗАМЕНИТЬ-НА-ССЫЛКУ-TELEGRAM"
  ]
}
</script>
```

Счётчик Метрики — если он ставится вручную, а не через раздел «Аналитика», то в том же поле head,
целиком и без правок, вместе с инлайн-стилями у `noscript`:

```html
<noscript><div><img src="https://mc.yandex.ru/watch/XXXXXXXX"
  style="position:absolute; left:-9999px;" alt="" /></div></noscript>
```

Проверка после публикации:

- Яндекс.Вебмастер → Инструменты → **Валидатор микроразметки**;
- Google **Rich Results Test**;
- Метрика → счётчик должен перейти в статус «Данные получены» (проверить, что счётчик ровно один —
  дубль счётчика ломает статистику, хотя вёрстку и не трогает).

## 5. Аварийный вариант, если код обязан остаться в теле страницы

Если по какой-то причине убрать блок T123 нельзя, его нужно вывести из потока. Узнать ID блока
(DevTools → атрибут `id="rec123456789"` у обёртки) и добавить в **Настройки сайта → Ещё → HTML-код
внутрь head**:

```html
<style>
  #rec123456789 { display: none !important; }
</style>
```

Скрипты внутри скрытого блока продолжают выполняться, поэтому счётчик работать не перестанет.
Это костыль: правильное решение — п. 3.

Если код вставлен в поле «внутрь body» и переносить его некуда, обернуть:

```html
<div style="display:none!important;height:0!important;overflow:hidden">
  <!-- код -->
</div>
```

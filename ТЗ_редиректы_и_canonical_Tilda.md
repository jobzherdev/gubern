# ТЗ — нормализация URL (слэш, множественные слэши) и canonical для gubernskaya-hotel.ru (Tilda)

**Задача:** свести все варианты одного адреса к одной корректной версии страницы:
- адреса **без `/` в конце** → на версию **со `/`**;
- «кривые» адреса с **множественными слэшами** (`/rooms///`, `//spa/`) → на одну корректную версию;
- тег **`rel="canonical"`** на страницах должен указывать на версию адреса **со `/` в конце**.

---

## 0. Ключевой факт, который решает архитектуру задачи

На **хостинге самой Тильды нет доступа к серверным правилам** (`.htaccess`, `nginx.conf`), поэтому
полноценную серверную нормализацию слэшей «внутри Тильды» сделать нельзя. Есть два ограничения:

1. **Встроенный инструмент «Редиректы страниц (Code 301)»** (Настройки сайта → SEO → Редиректы)
   срабатывает **только для НЕсуществующих страниц**. Для перехода между двумя *существующими*
   URL Тильда предлагает блок T223 (JS-редирект), но он не даёт серверного 301 и не подходит
   для массовой нормализации.
   → Значит, редирект «существующий URL без слэша → URL со слэшем» встроенным инструментом
   Тильды **не делается**.

2. **Нативная форма URL в Тильде — БЕЗ слэша на конце** (`/rooms`, `/spa`). Все внутренние
   ссылки (меню, кнопки) Тильда генерирует именно без слэша. Требование «канон со слэшем»
   идёт против дефолта платформы, поэтому:
   - canonical придётся **переопределять вручную на каждой странице**;
   - каждый клик по внутренней навигации будет ловить лишний 301-хоп (без→со слэшем).

> **Рекомендация SEO (важно согласовать с клиентом до внедрения):**
> технически проще и «чище» канонизировать в **нативную для Тильды форму — БЕЗ слэша**.
> Это убирает все лишние редиректы внутренней навигации и не требует ручного canonical.
> Google и Яндекс трактуют `/rooms` и `/rooms/` как один документ и корректно склеивают дубли
> по canonical, так что с точки зрения индексации разница минимальна.
> **Если требование «со слэшем» жёсткое** — оно выполнимо, но **только через слой перед Тильдой**
> (Cloudflare) или через экспорт на свой сервер (Варианты B / C ниже).

Дальше — как выполнить именно требование «канон = со `/`».

---

## 1. Что делаем внутри Тильды (обязательная база, при любом варианте)

### 1.1. Canonical со слэшем на каждой странице
Для каждой страницы: **Настройки страницы → SEO (Facebook и SEO / Ещё) → «Каноническая ссылка на
страницу»** — прописать полный URL со слэшем на конце, например:
```
https://gubernskaya-hotel.ru/rooms/
```
Для главной canonical = `https://gubernskaya-hotel.ru/`.
По умолчанию Тильда ставит self-canonical на нативную (без слэша) форму — поэтому поле нужно
заполнить руками, иначе canonical будет указывать на версию без слэша и противоречить редиректам.

> Массово удобно вести реестром: страница → её canonical-URL (см. чеклист в разделе 4).

### 1.2. Встроенные 301 — только для «мусорных»/старых URL
Настройки сайта → SEO → **Редиректы страниц (Code 301)**. Поддерживается маска `*`.
Использовать для карты 301 со старого сайта и для явных несуществующих мусорных путей.
Для нормализации слэшей существующих страниц этот инструмент **не сработает** (см. п.0).

### 1.3. Единый sitemap и внутренние ссылки
- В `sitemap.xml` перечислить URL **только в канонической форме (со слэшем)**.
- Внутренние ссылки по возможности вести на форму со слэшем (в Тильде это ограничено —
  меню генерит без слэша; поэтому слой-редиректор из раздела 2 обязателен, чтобы клики
  не отдавали 200 на неканонической форме).

## 2. Вариант B (рекомендуемый для требования «со слэшем») — Cloudflare перед доменом

Тильда позволяет подключать домен через сторонние DNS. Ставим **Cloudflare** в режиме
проксирования (оранжевое облако) и делаем настоящие серверные 301 на «крае», до Тильды.

**Подключение:** домен `gubernskaya-hotel.ru` переводится на NS Cloudflare, A/CNAME-записи —
на IP/хост Тильды (по инструкции Тильды для внешних DNS), проксирование включено.

**Rules → Redirect Rules** (создать правила по порядку; тип ответа — 301):

**Правило 1. Схлопнуть множественные слэши (`//` → `/`).**
*Требует regex — доступно на планах Business+ (функция `regex_replace`).*
```
When incoming requests match:
  (http.request.uri.path matches "//+")
Then:
  Dynamic redirect →
  concat("https://gubernskaya-hotel.ru",
         regex_replace(http.request.uri.path, "/{2,}", "/"))
  Preserve query string: ON
  Status: 301
```

**Правило 2. Добавить слэш в конце (если его нет и это не файл).**
*Regex не нужен — работает и на бесплатном плане.*
```
When incoming requests match:
  (not ends_with(http.request.uri.path, "/")
   and not http.request.uri.path contains ".")
Then:
  Dynamic redirect →
  concat("https://gubernskaya-hotel.ru", http.request.uri.path, "/")
  Preserve query string: ON
  Status: 301
```

**Правило 3 (гигиена канона хоста). Привести к https + без www.**
```
When: (http.host eq "www.gubernskaya-hotel.ru") or (ssl eq false)
Then: 301 → concat("https://gubernskaya-hotel.ru", http.request.uri.path)
      Preserve query string: ON
```

> **Ограничение бесплатного плана Cloudflare:** схлопывание множественных слэшей (Правило 1)
> использует `regex_replace` и доступно только на Business+. На free-плане закрываем trailing
> slash (Правило 2) и хост/https (Правило 3), а «кривые» `///` дополнительно гасит canonical
> (раздел 1.1) — поисковики склеят дубли по нему. Если `///` встречается массово в логах —
> апгрейд плана либо Вариант C.

## 3. Вариант C — экспорт сайта и хостинг на своём сервере (полный контроль)

Если проект уходит с хостинга Тильды на свой сервер (nginx/Apache) — правила пишутся напрямую.

**Apache (`.htaccess`):**
```apache
RewriteEngine On

# 1. Схлопнуть множественные слэши в пути
RewriteCond %{REQUEST_URI} ^(.*?)//+(.*)$
RewriteRule . %1/%2 [R=301,L]

# 2. Добавить слэш в конце, если это не файл
RewriteCond %{REQUEST_FILENAME} !-f
RewriteCond %{REQUEST_URI} !/$
RewriteRule ^(.*)$ /$1/ [R=301,L]
```

**nginx:**
```nginx
# merge_slashes on;  — включено по умолчанию, схлопывает // в путях
location / {
    if ($request_uri ~ ^([^?]*[^/])($|\?)) {
        return 301 $1/;
    }
    # ... proxy_pass / try_files
}
```
После экспорта canonical всё равно держим со слэшем (раздел 1.1) — правила и тег согласованы.

- [ ] Согласовать с клиентом форму канона (рекомендация — без слэша; требование ТЗ — со слэшем).
- [ ] Проставить canonical со `/` на всех страницах (реестр «URL → canonical»).
- [ ] Выбрать слой нормализации: Cloudflare (B) или свой сервер (C). На «голой» Тильде
      серверный 301 без слэша→со слэшем недостижим.
- [ ] Настроить редиректы: множественные слэши, trailing slash, https, www→non-www.
- [ ] `sitemap.xml` — только канонические URL (со слэшем).
- [ ] Проверить, что каждый неканонический вариант отдаёт **один 301** на канонический
      (без цепочек): `/rooms` → `/rooms/`, `/rooms///` → `/rooms/`, `//rooms` → `/rooms/`.
- [ ] Проверить `curl -I` по всем вариантам, что финальный URL = canonical и код 200.

## 5. Резюме одним абзацем

Полноценные серверные 301 для нормализации слэшей на **хостинге Тильды невозможны** (нет доступа
к серверу, встроенный 301 работает только по несуществующим URL). Поэтому: **canonical со `/`
проставляем вручную на каждой странице внутри Тильды**, а **массовую серверную нормализацию
(trailing slash + множественные слэши) делаем слоем перед Тильдой через Cloudflare Redirect Rules**
(или на своём сервере после экспорта). Технически проще канонизировать в нативную для Тильды
форму без слэша — это стоит проговорить с клиентом до внедрения.
